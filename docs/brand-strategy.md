# Kanon Studio — ブランド設計 v1

作成日: 2026-10-17。現状のコードとユーザーの希望をもとにした運用設計。認知調査・音源の比較試聴・競合比較・成果測定は未実施。対象層、ポジショニング、作品の代表性は仮説として検証する。

## 1. 目的と成功条件

作品を見た人が「可愛い絵だった」で終わらず、Kanon Studioの作品として覚え、もう一曲・もう一作品を楽しみ、再訪できる状態を目指す。説明文の追加ではなく、絵・音・操作・継続した見せ方で伝える。

認知（誰の作品か）・選好（なぜまた楽しみたいか）・利用（実際に聴いたか）は別々に確かめる。閲覧数だけでブランドが強くなったとは判断しない。

## 2. ポジショニング仮説

| 項目 | 作業仮説 / 決定済み事項 |
| --- | --- |
| 最初に検証する相手 | SNSでキャラクターイラストに惹かれ、音楽も試してみたい人。既存フォロワーと初見の人を区別する |
| 訪問のきっかけ | 投稿の絵が気になる / 新曲を聴く / もう一度あの作品に触れたい |
| 提供する体験 | 絵を入口に、その場で曲を聴き、別の作品にも出会える |
| 個性の仮説 | 可愛いキャラクターと強いビート、明暗のある作品世界の組み合わせ。全曲に同じ音楽ジャンルを強制しない |
| 既にある裏付け | 実在する音楽・イラスト・ゲーム、サイト内の30秒試聴、作品紹介 |
| 未検証のこと | この組み合わせが選ばれる理由か、競合と比べて違いとして認識されるか、代表作はどれか |

これは内部の判断基準であり、トップに表示するキャッチコピーではない。「AIで制作」は制作方法の説明として必要な場所に記す。独自性・品質の証明と同一視しない。

## 3. ブランドの構造

- Kanon Studio: 音楽・絵・ゲームを包含する作品世界と制作活動の名前。
- @phstarrion: 作者・発信元。公開済みの接続先を使用する。
- 看板キャラクター: 視覚的な顔。名前、作者の分身という設定、架空の経歴は未決定。
- 各楽曲・シリーズ・ゲーム: それぞれの作品名を尊重する。全作品へ看板キャラを強制しない。

## 4. 識別資産の設計

「目立つ」と「Kanon Studioのものとわかる」は別。下記は育成候補であり、現時点で独自の識別力が証明された資産ではない。

| 資産 | 役割 | 運用 |
| --- | --- | --- |
| 指定された看板キャラの顔 | 最優先の識別資産候補 | まずスタジオ名と組み合わせて反復する。顔立ち・瞳・白銀の髪・猫耳・眼鏡・星飾りを基準にする |
| Kanon Studioの表記 | 名前との結び付け | 表記を固定。小さい表示での読みやすさを優先する |
| 濃紺・白・ラベンダー | 共通の雰囲気と操作の手掛かり | 作品そのものの色は自由。色だけで作者が判別できるとは考えない |
| 金の星 | キャラクターと名前をつなぐ補助 | 一般的な星単体を独自ロゴと扱わない。小さく併用する |
| 月・音楽室 | 場所の雰囲気 | 既存トップの世界観。看板キャラの顔とは役割を分ける |
| 音の特徴・短い音の目印 | 将来の候補 | 音源を聴いて検討する。現時点でジングルは作らず、試聴に挿入しない |

固定: 顔の同一性、名前の表記、操作の意味、書体の役割、基本の余白。可変: 作品の色、衣装、ポーズ、構図、ジャンル。新しい別カットは原画と並べ、顔・耳・瞳・眼鏡・髪・飾りの位置関係を確認してから使う。

## 5. 接点の監査と改善順

| 接点 | 2026-10-17時点の確認 | 対応 |
| --- | --- | --- |
| トップのメイン画像 | 既存の音楽室イラスト。ユーザーが継続を指定 | 維持。説明文を重ねない |
| トップ下部の活動紹介 | 旧青髪ポートレートが残り、About・フッターの新しい顔と不一致 | 今回、指定の看板キャラに統一 |
| About・全ページのフッター | 指定原画と名前を使用 | 継続。目印を頻繁に作り直さない |
| おすすめ曲 | 音源がある新しい3曲。代表性の比較は未実施 | 当面維持。「最新」と「代表」を混同しない |
| ヘッダー・favicon | 月のモチーフ | 今回変更しない。16〜32pxの判別性を確認してから検討 |
| SNSプロフィール・投稿画像 | 本作業ではアカウント表示を未監査 | 次段階で既存表示を確認し、共通テンプレートを用意。勝手にプロフィール変更や投稿はしない |

次の制作候補は、作品画像を主役にし、同じ余白・名前・小さな識別資産を反復するSNS紹介テンプレート。新しいロゴ案を毎回作るより、採用した見せ方を蓄積する。

## 6. 作品の編集方針

- 代表作は再生可能であることを前提に、絵と音の一致、聴きどころへの入りやすさ、現在目指す体験の伝わり方を比較して選ぶ。
- 今回は音源を比較試聴していないため代表作を決めない。人気順・成果が出た作品とも称さない。
- ジャケットや紹介文から期待される体験と、実際の30秒試聴に差がないかを確認する。
- 操作の主役は試聴。キャラクターの装飾・SNSリンクが再生操作より強くならないようにする。
- 動きは作品の発見や操作の反応に使う。ブランド感のためだけに常時点滅、音の自動再生、待ち時間を追加しない。

## 7. 調べ方と測定

### 小規模な認知確認（未実施）

既存の閲覧者と初見の人を混ぜずに記録する。まず各群数人で質問の意味が通じるかを試す。誘導を避け、以下の順で聞く。

1. 絵や投稿見本を5秒見てもらい、閉じたあと「何が印象に残ったか」を自由回答。
2. 名前を伏せた看板キャラを見せ、「誰・どのサイトのものだと思うか」を自由回答。「わからない」も受け付ける。
3. 「ほかの作者やブランドも思い浮かぶか」を自由回答し、誤認を記録する。
4. サイトで好きな曲を1曲再生してもらい、迷った場所と操作を観察する。目的達成までの行動と、感想を分けて記録する。

少人数の結果は問題を見つける材料とし、認知率・独自性の人口推計や統計的な効果の証明にしない。名前を知らない初見の人に認知の正答を期待しない。初見では体験と記憶に残った特徴を優先して見る。

### ウェブ上の行動

現行コードには訪問・流入元といいねの送信がある。今回、集計値は取得していない。試聴開始・完了・別曲への移動・再訪の専用集計があるとは確認できていないため、試聴率や再訪率を報告しない。

将来の計測候補: 試聴可能なページ訪問あたりの再生開始、再生開始後の別曲再生、再訪。追加時は保存先・分母・重複・期間を定義し、既存の流入元を分けて見る。無断で外部トラッキングを追加しない。流入や作品が違う期間比較を、ブランド変更の因果効果と断定しない。

## 8. 継続改善の判定

更新前に「識別・選ばれる理由・体験・再訪のどれを改善するか」を一つ決め、変更、根拠、検証範囲を記録する。文字量、飾り、色数、アニメーションの量を成果指標にしない。

運用順: 接点の不統一を修正 → 同じ識別資産で作品紹介テンプレートを作る → 絵と音の期待を確かめて代表作を選ぶ → 認知と操作を観察 → 結果に応じて一つずつ変更。これらは実行候補であり、調査やSNS投稿、追加の自動実行を設定したという意味ではない。

上記の考え方を個人の創作サイト向けに適用した設計案。各社の正式な調査を実施した、認証を受けた、独自性が実証されたという意味ではない。
